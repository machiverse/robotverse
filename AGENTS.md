# Project rules
- Uploaded standalone project documents run in script-only sandboxed iframes with raw imports; standalone entry paths bypass marketplace providers/popups so scripts, styles and controls remain isolated.
- RoboBook grid cards mount owner actions outside their navigation link and target the post's original store; community publication changes use the shared helper and blog autosave preserves publication state.
- Robot simulator rigid meshes are baked by material/shadow flags; mark mutable subtrees dynamic and preserve asset-factory pools during transient cleanup to prevent animation regressions and leaks.
- Simulator mutations are coalesced by the frame stepper; screens use setEquipmentAll and wait for readiness before queries so user actions do not trigger synchronous rebuild cascades.
- In development, each simulator canvas exposes __robotSimulation for browser performance checks; stats() flushes pending work and reports complete frame counters and rebuild count.
- Automation analysis scenes use the additive station-preserving machineScene adapter; legacy skill exports remain unchanged, and optional machine instances share simulator baking/cleanup so evidence and repeated operations survive without altering default jobs.
- Studio media and solution analysis use the shared server-only Claude adapter with verified user sessions; keep secrets out of the client and retain ordered evidence-bearing stations so the report and scene describe the same process.
- The shared Claude adapter forwards ANTHROPIC_WORKSPACE_ID when configured and classifies provider errors without exposing raw messages, because organization-scoped keys require explicit workspace selection.
- Uploaded Studio evidence initializes and synchronizes scene workpieces and ordered stations; keep it authoritative over later text-only refinements so identical job names cannot leave a stale item or machine visible.
